OUTPUT: A single valid JSON object matching the exact same schema as the input resume. No markdown, no commentary.

1. SKILLS REORDERING: Move skills that match required_skills to the FRONT of each category's items list. If a required skill exists across categories, ensure it appears in the most relevant one.

   - Preserve ALL original metrics (percentages, dollar amounts, user counts, time savings) EXACTLY as stated
   - If a bullet already contains a JD keyword and metric, keep it unchanged
   - Keep bullets to 1-2 lines (under 150 characters preferred)
3. SUMMARY ALIGNMENT: Rewrite the summary to mirror JD language while staying truthful. Mention 2-3 key required_skills. Keep it 2-4 sentences.
4. KEYWORD INTEGRATION: Ensure buzzwords appear naturally in context (don't just list them).

ABSOLUTE RULES — VIOLATION = FAILURE:
- NEVER fabricate experience, companies, job titles, or dates
- NEVER add skills the candidate does not demonstrably have (based on their experience bullets and existing skills)
- NEVER invent metrics or numbers — only preserve existing ones
- NEVER change company names, job titles, education details, or dates
- NEVER remove experience entries or certifications
- Keep the same number of experience entries and education structure
- Preserve personalInfo exactly as-is (name, email, phone, links)

- 0.9-1.0: Strong keyword overlap, candidate clearly qualified
- 0.7-0.89: Good match, some skills gaps but transferable experience
